# Выкатка на рабочий контур и порядок тестирования

Документ для того, кто ставит плагин на рабочий GLPI. Версия **1.0.0-rc7** —
кандидат: функционально полный, проверенный на стенде, предназначенный для
опытной эксплуатации на ограниченном круге сотрудников.

---

## 1. Требования

| Что | Значение |
|---|---|
| GLPI | 11.0 и новее (проверено на 11.0.8) |
| PHP | та же версия, что требует ваша сборка GLPI |
| Планировщик | системный cron GLPI должен работать: три задания плагина работают во внешнем режиме |
| Права на файлы | каталог `plugins/` доступен на запись пользователю веб-сервера |
| Доступ | администратор GLPI с полными правами (установка плагина и правка профилей) |

## 2. Перед установкой

- [ ] **Резервная копия базы данных** и каталога GLPI. Плагин не меняет схему
      GLPI, но откат всегда проще из копии.
- [ ] Проверить версию GLPI: **Настройки → Общие → Система**.
- [ ] Убедиться, что каталога `plugins/storefront` ещё нет (или сохранить
      старую копию отдельно).
- [ ] Проверить, что cron GLPI работает: **Настройка → Автоматические
      действия** — у штатных заданий заполнена дата последнего запуска.
- [ ] Решить, кто будет администратором витрины и кто кладовщиком, и в каких
      организациях назначить им профили.
- [ ] Выдать профилю согласующих штатное право GLPI **«Согласование заявок» →
      «Согласовать запрос»**: без него руководитель не откроет заявку, в
      которой должен ответить.

## 3. Установка

1. Распаковать каталог `storefront` в `plugins/` вашей установки GLPI.
2. Выполнить от пользователя веб-сервера:

```
php bin/console plugin:install storefront
php bin/console plugin:activate storefront
```

Через веб-интерфейс — то же самое: **Настройки → Плагины → Внутренний магазин
→ Установить → Включить**.

### Что появится в системе

| Что | Подробности |
|---|---|
| 14 таблиц | `glpi_plugin_storefront_catalogs`, `…_warehouses`, `…_products`, `…_stocks`, `…_movements`, `…_orders`, `…_orderitems`, `…_limits`, `…_kits`, `…_kititems`, `…_kitgrants`, `…_ratings`, `…_titlelevels`, `…_cartitems` |
| 3 права | «Витрины, номенклатура, наборы и лимиты», «Заказы: очередь комплектования и выдача», «Склад: остатки, приход, списание, перемещение» — выдаются на вкладке «Внутренний магазин» формы профиля |
| 3 задания | `storefront_lowstock` (сутки), `storefront_cartcleanup` (неделя), `storefront_reserves` (сутки) |
| Пункт меню | **Управление → Магазин** |
| Вкладка | «Внутренний магазин» на форме профиля |

Схема GLPI не меняется. Заявки, запросы согласования, комментарии, решения и
расходные материалы плагин создаёт штатным API GLPI — так же, как это сделал бы
человек в интерфейсе.

## 4. Проверка сразу после установки

| № | Что проверить | Ожидаемый результат |
|---|---|---|
| 1 | **Настройки → Плагины** | «Внутренний магазин», версия 1.0.0-rc7, состояние «Включён» |
| 2 | **Управление → Магазин** | пункт есть, открывается список витрин (пустой) |
| 3 | Подпункты меню | Витрины магазина, Очередь заказов, Заказы, Загрузка номенклатуры, Склад, Аналитика, Отчёты, Уровни должностей |
| 4 | **Администрирование → Профили → любой профиль** | есть вкладка «Внутренний магазин» с тремя правами |
| 5 | **Настройка → Автоматические действия** | три задания `storefront_*` присутствуют и включены |
| 6 | Журнал `files/_log/php-errors.log` | нет новых записей со словом `storefront` |
| 7 | Журнал `files/_log/sql-errors.log` | нет новых записей |
| 8 | Открыть страницы плагина по очереди | все отвечают без ошибок; пустые списки — это нормально |

Если пункт меню не появился — обновите страницу с очисткой кеша браузера и
проверьте, что плагин именно «Включён», а не только «Установлен».

## 5. Пилот: как тестировать

Ставить сразу на всех не нужно. Порядок, проверенный на стенде:

1. **Одна витрина.** Настройте её по [setup-example.md](setup-example.md).
   Начните с той, где номенклатура простая и выдача частая — канцелярия
   подходит лучше техники.
2. **Ограниченный круг.** Дайте плитку одному подразделению: 5–10 сотрудников,
   один-два согласующих, один кладовщик.
3. **Одна-две недели.** За это время проходят все ветки: обычная выдача,
   частичная выдача, отказ, отмена, пополнение склада, срабатывание лимита.
4. **Разбор.** Соберите с кладовщика и сотрудников, что было непонятно:
   формулировки правятся настройками витрины (описание, объявление, названия
   позиций) без правки кода.

### Что обязательно проверить в пилоте

- [ ] Сотрудник находит витрину плиткой, не спрашивая, «где это».
- [ ] Заказ дешевле порога уходит на склад без согласования; дороже — приходит
      руководителю.
- [ ] Согласующий открывает заявку и отвечает кнопками (право «Согласование
      заявок» выдано).
- [ ] Отказ согласующего: заявка получает решение и статус **«Решена»**, склад
      не тронут, сотрудник видит причину.
- [ ] Кладовщик уменьшает количество с причиной — сотрудник видит причину в
      заявке.
- [ ] Выдача списывает остаток ровно на выданное; накладная печатается и
      подписывается.
- [ ] Жёсткий лимит останавливает заказ и сообщает, чей запас исчерпан.
- [ ] Заявки получают сроки SLA по категории витрины.
- [ ] Через сутки после установки задание `storefront_reserves` отработало
      (**Настройка → Автоматические действия → storefront_reserves**, дата
      последнего запуска заполнена).

### Что смотреть в данных раз в несколько дней

| Где | На что смотреть |
|---|---|
| **Управление → Магазин → Склад** | нет отрицательных остатков; резерв не больше остатка без причины |
| **Управление → Магазин → Аналитика** | выдачи попадают в отчёт, срок исполнения похож на реальный |
| `files/_log/php-errors.log` | записи со словом `storefront` |
| **Настройка → Автоматические действия** | все три задания отрабатывают |

## 6. Обновление версии

1. Заменить каталог `plugins/storefront` новой версией.
2. **Обязательно** выполнить миграцию:

```
php bin/console plugin:install storefront
php bin/console plugin:activate storefront
```

> До миграции GLPI считает плагин требующим обновления и **не загружает его
> классы**: страницы магазина будут отдавать ошибку, а плитка исчезнет.
> Это штатное поведение GLPI, а не сбой — просто выполните две команды.

Данные при обновлении сохраняются: миграция добавляет недостающие столбцы и
права, ничего не удаляя.

## 7. Откат

**Отключить, сохранив данные:** **Настройки → Плагины → Отключить**. Витрина
исчезнет из меню и из самообслуживания, заказы и остатки останутся в базе.
Включение возвращает всё как было.

**Удалить плагин:** **Настройки → Плагины → Удалить**. Что происходит:

| Данные | Что с ними |
|---|---|
| Заказы, строки заказов, движения склада, остатки | **остаются** в базе как есть — это учётные данные |
| Витрины, склады, позиции, лимиты, наборы, разрешения, оценки, уровни должностей | таблицы переименовываются с суффиксом даты (`…_backup_ГГГГММДД`) |
| Корзины | удаляются |
| Права магазина | снимаются со всех профилей |
| Заявки, решения, комментарии | остаются: это данные GLPI, не плагина |
| Расходные материалы GLPI | остаются: плагин их только использовал |

Полная зачистка (если данные больше не нужны) делается вручную: удалить
таблицы `glpi_plugin_storefront_*` и их резервные копии `…_backup_*`.

## 8. Что учесть до массового запуска

**Не реализовано** (не дефекты, а невыполненный объём):

- учёт по инвентарным номерам — выдаётся расходное количество, а не конкретный
  экземпляр с номером;
- позиция «нет в каталоге» — заказать свободным текстом то, чего нет в
  номенклатуре, нельзя.

**Особенности, о которых стоит договориться заранее:**

- **Лимит считает период целиком**, включая выдачи, сделанные до того, как
  правило завели. Правило «одно кресло в год», введённое в сентябре, посчитает
  и январское кресло.
- **Норма лимита** — решение организационное: «у каждого своя» или «одна на всю
  область». Для дорогих позиций общая норма отдела обычно ближе к жизни.
- **Заказ на отдел или подразделение** расходует норму этого отдела, а не
  личную норму того, кто расписался в накладной. Если это нежелательно —
  ограничьте круг тех, кто может заказывать не для себя, либо задайте общую
  норму области.
- **Резерв мягкий**: обещание может превысить фактический остаток, нехватка
  обнаружится при выдаче. Это осознанный выбор, чтобы один заказ не блокировал
  склад для всех.

## 9. Приёмка

Плагин можно считать готовым к массовому запуску, когда за время пилота:

- [ ] прошло не меньше 20 заказов, включая отказ, отмену и частичную выдачу;
- [ ] в журналах нет ошибок со словом `storefront`;
- [ ] остатки склада сходятся с фактом при выборочном пересчёте;
- [ ] кладовщик работает в очереди без обращений «а как здесь…»;
- [ ] сроки SLA по заявкам витрины считаются и соблюдаются;
- [ ] задания планировщика отрабатывают ежедневно.
